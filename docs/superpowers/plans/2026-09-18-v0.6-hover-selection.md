**Goal:** 用户已经在任意应用里框选了一整段句子时，按住触发键（Option）把指针移到这段选区上停住，就直接出现浮窗并翻译**整个选区**——不需要按选区快捷键、不需要复制粘贴、不读剪贴板、不新增权限。

**Architecture:** 不新建第二条链路。悬停读取层（AX）在原有的取词顺序之前增加一次"焦点选区命中"探测：命中就返回一个 `scope == .selection` 的 `ExtractionSnapshot`，未命中就一字不改地走现有的单词/整句/标签路径。协调器、浮窗、请求构造、缓存键、设置界面全部不动——它们已经支持 `.selection`。

**Tech Stack:** Swift、SwiftUI、AppKit、ApplicationServices（AX）。本版不引入任何新依赖、不新增权限、不新增网络行为。

## 0. "完成"的可观测定义

在真实应用（至少 TextEdit，以及用户日常的第二个应用）里：

1. 选中一整句英文 → 按住触发键 → 把指针移到选区上停住 → 250 ms 稳定后浮窗出现，**原文逐字符等于选区文本**，随后出现中文译文；
2. 全程不按任何快捷键、不写剪贴板、不新增权限、不弹额外窗口；
3. 指针不在选区内（或根本没有选区）时，行为与现状 **完全一致**（单词 / 触发键+Control 整句 / 标签 / OCR 策略都不变）；
4. 自动化测试全绿且数量 ≥ 现有基线 205 + 本版新增；Debug/Release 构建退出码 0、本项目源码 0 warning；
5. 选区快捷键入口（默认 Control-Command-T）行为不变（回归项 G10）；
6. 未实机验证的项（某些应用的 AX 能力）在 `docs/ACCEPTANCE.md` 里如实标 NOT RUN / NOT SUPPORTED，不猜、不用示例 PASS 冒充。

## 3. 判定规则表（实现、测试、用户指南都以这张表为准）

| 情形 | 行为 |
|---|---|
| 触发键未按住 | 一次 AX 调用都不发（沿用现有门 `samplePointer` 的 `isTriggerHeld`；指针移动本身不读任何 AX） |
| 触发键按住、指针未稳定 | 不发（沿用 250 ms / 4 点 dwell） |
| 焦点控件没有选区（`AXSelectedTextRange` 长度 0） | 走现有单词/整句路径，不读正文 |
| 指针在选区屏幕矩形之外 | 走现有单词/整句路径 |
| 指针在矩形内、但序号判定（`AXRangeForPosition`）落在选区之外 | 走现有路径（多行选区的并集矩形误命中被这一条挡掉） |
| 应用不支持 `AXRangeForPosition` | 只用几何判定（如实登记为"多行选区边缘可能偏宽"的限制） |
| 指针在选区内 + 按住 Control | **选区优先**，结果仍是整段选区（Control 在选区内不改变结果，写进用户指南） |
| 选区文本超过 4000 字符（或全为空白） | 拒绝：不截断、不发送、不显示；回落到现有单词/整句路径，指南里指向快捷键/手动入口 |
| 焦点控件是密码/安全控件 | 拒绝读取（沿用 `isProtected`），回落现有路径 |
| 焦点控件的 pid ≠ 指针下窗口属主 pid | 拒绝（不读后台窗口的选区），回落现有路径 |
| 焦点应用在用户的排除列表里 | 根本进不到读取层：协调器在取词前已按 bundleID 拒绝（`TranslationCoordinator.swift:464-475`） |
| 卡片处于固定状态 | 沿用 `lifecycle.acceptsNewContent == false`，新悬停不覆盖 |
| 松键后迟到的选区结果 | 沿用代次门丢弃（已有测试覆盖，本版不重复造） |
| 命中但读不到文本（应用不回 `AXSelectedText`/`StringForRange`） | 回落现有路径，不猜、不用剪贴板补 |
| 选区快捷键（Control-Command-T） | 行为不变（回归项） |

## 4. 纯函数契约（任务 1 的实现契约）

判定逻辑必须能脱离 AX 单独测试；AX 那半边只做接线，不藏判定。

```swift
import CoreGraphics

/// 指针是否落在"当前选区"上。三个输入互相独立，组合规则只有一条。
enum SelectionHitPolicy {
    /// 容差初值：只覆盖像素取整，不足以覆盖相邻文字（设计初值，不是实测值）。
    static let tolerance: CGFloat = 2

    /// 矩形包含：边界算命中（鼠标停在选区最后一个像素上仍然算）。
    static func isInside(_ point: CGPoint, rect: CGRect, tolerance: CGFloat = tolerance) -> Bool {
        rect.insetBy(dx: -tolerance, dy: -tolerance).contains(point)
    }

    /// 两个字符范围是否相交。空选区（length == 0）永远不算命中。
    /// 相邻（pointer.location == selected.location + selected.length）不算相交。
    static func overlaps(_ pointerRange: CFRange, selectedRange: CFRange) -> Bool

    /// 唯一组合规则：几何必须命中；应用报得出指针处字符范围时，序号也必须命中。
    /// pointerRange == nil 表示应用不支持该属性，此时只用几何。
    static func isHit(pointer: CGPoint,
                      selectionRect: CGRect,
                      pointerRange: CFRange?,
                      selectedRange: CFRange,
                      tolerance: CGFloat = tolerance) -> Bool
}
```

测试片段（`HoverTranslateTests/SelectionHitPolicyTests.swift`，先红后绿；全部合成数据）：

```swift
import XCTest
@testable import HoverTranslate

final class SelectionHitPolicyTests: XCTestCase {
    private let rect = CGRect(x: 100, y: 200, width: 300, height: 20)
    private let selected = CFRange(location: 10, length: 32)

    func testPointerInsideTheSelectionRectIsAHit() {
        XCTAssertTrue(SelectionHitPolicy.isHit(pointer: CGPoint(x: 250, y: 210),
                                               selectionRect: rect,
                                               pointerRange: CFRange(location: 20, length: 5),
                                               selectedRange: selected))
    }

    func testPointerOutsideTheSelectionRectIsNeverAHit() {
        XCTAssertFalse(SelectionHitPolicy.isHit(pointer: CGPoint(x: 250, y: 260),
                                                selectionRect: rect,
                                                pointerRange: CFRange(location: 20, length: 5),
                                                selectedRange: selected))
    }

    func testEmptySelectionIsNeverAHit() {
        XCTAssertFalse(SelectionHitPolicy.isHit(pointer: CGPoint(x: 250, y: 210),
                                                selectionRect: rect,
                                                pointerRange: CFRange(location: 0, length: 4),
                                                selectedRange: CFRange(location: 0, length: 0)))
    }

    /// 多行选区的并集矩形覆盖了未被选中的文字：序号判定必须把它挡掉。
    func testIndexTestRejectsAPointInsideTheUnionRectButOutsideTheSelection() {
        XCTAssertFalse(SelectionHitPolicy.isHit(pointer: CGPoint(x: 250, y: 210),
                                                selectionRect: rect,
                                                pointerRange: CFRange(location: 60, length: 5),
                                                selectedRange: selected))
    }

    /// 应用不支持 AXRangeForPosition：几何是唯一依据（如实降级，不猜序号）。
    func testGeometryAloneDecidesWhenTheAppReportsNoRange() {
        XCTAssertTrue(SelectionHitPolicy.isHit(pointer: CGPoint(x: 250, y: 210),
                                               selectionRect: rect,
                                               pointerRange: nil,
                                               selectedRange: selected))
        XCTAssertFalse(SelectionHitPolicy.isHit(pointer: CGPoint(x: 250, y: 260),
                                                selectionRect: rect,
                                                pointerRange: nil,
                                                selectedRange: selected))
    }

    func testToleranceOnlyCoversPixelRounding() {
        XCTAssertTrue(SelectionHitPolicy.isInside(CGPoint(x: 99, y: 210), rect: rect))
        XCTAssertFalse(SelectionHitPolicy.isInside(CGPoint(x: 96, y: 210), rect: rect))
    }

    func testAdjacentRangesDoNotOverlap() {
        XCTAssertFalse(SelectionHitPolicy.overlaps(CFRange(location: 42, length: 3), selectedRange: selected))
        XCTAssertFalse(SelectionHitPolicy.overlaps(CFRange(location: 7, length: 3), selectedRange: selected))
        XCTAssertTrue(SelectionHitPolicy.overlaps(CFRange(location: 40, length: 3), selectedRange: selected))
    }
}
```

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| 某应用不提供 `AXRangeForPosition` | 只用几何判定，功能仍可用；登记为"多行选区边缘可能偏宽"的限制 |
| 某应用不提供 `AXBoundsForRange` 或 `AXSelectedText` | 该应用里这个手势不可用（回落到原单词悬停），**不猜、不 OCR、不读剪贴板**；指南里写明仍可用快捷键入口 |
| 每次 dwell 开始多出 AX 调用 | 常见负例只多 2 次调用（焦点控件 + 选中范围），命中时约 5 次；全部沿用 0.3 s 超时。若 G11 实测悬停延迟明显变差，加一个 **0 次 AX 调用**的前置门：指针下窗口属主 ≠ `NSWorkspace.frontmostApplication` 时直接跳过探测 |
| 多行选区的并集矩形把未选中文字算成命中 | 序号判定挡掉（任务 1 的 `testIndexTestRejectsAPointInsideTheUnionRectButOutsideTheSelection`） |
| 用户在选区内其实只想要那个单词 | 规则明确：选区内悬停永远翻译整个选区；想要单词先点一下取消选区（点击本来就会取消并重新计时）。写进用户指南 |
| 隐私口径被扩大 | 只在"触发键按住 + 指针稳定"后查询范围与矩形，只有指针落在选区内才读正文；设计文档与指南同步写明 |
| 两个选区入口（悬停=浮窗 / 快捷键=手动窗口）让人困惑 | 保持不动，指南里写清区别；如用户想统一到浮窗，另开一版，不在本版顺手改 |
| 改动波及既有 205 项测试 | 协调器/卡片/请求层零改动；只新增文件与一个测试，全量回归必须 0 失败、0 跳过 |
