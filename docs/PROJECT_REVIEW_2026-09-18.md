## 2. 项目目标与现状

HoverTranslate 是独立的 macOS 菜单栏工具，帮助用户在保留英文软件界面的同时按需理解内容。默认右 Option 悬停取词，可切换左 Option；Option + Shift 获取整句；另有选区翻译、手动输入、主动收藏与按需解释。

技术实现为 Swift / SwiftUI / AppKit，最低部署目标 macOS 14.0；AX 优先取词，ScreenCaptureKit 获取局部单帧，Vision 本机 OCR，URLSession 接入 DeepSeek，Keychain 保存用户输入的密钥。当前有 40 个应用 Swift 源码文件、21 个测试文件。

当前范围是本机自用，不包含 App Store 发布、账号同步、离线翻译、发音、自动复习或多引擎扩展。

## 3. 问题清单与解决方案

### R1 · P1 · 选区入口绕过排除列表，来源归属不可靠

**证据：源码确认。**

- `AGENTS.md` 要求排除列表内应用“一律不读取”，未知来源也应拒绝。
- `Input/SelectionShortcutController.swift` 的 `handle` 用鼠标位置确定来源，随后异步调用 `selectedText()`。
- `Extraction/SelectionTextExtractor.swift` 实际读取系统焦点元素的选区，没有排除列表检查，也没有将焦点元素 PID 与此前来源核对。
- `Core/TranslationCoordinator.swift` 的 `handleSelection` 明确不以来源限制请求。

**影响：** 被排除应用仍可能经快捷键读取并翻译选区。鼠标所在窗口与键盘焦点不一致时，记录的来源可能并非实际被读取的应用。这里只能确认代码路径存在缺口，不能声称已经发生真实信息泄露。

**解决方案：**

1. 快捷键入口先检查功能启用状态，再获取焦点元素的实际 PID、bundle ID 和安全角色；读取选区正文前执行来源策略。
2. 在同一受控提取流程内完成来源确认与正文读取，返回包含来源和请求代次的值快照。不要把鼠标下窗口当成选区来源。
3. 读取完成后、上传前再次核对请求有效性与最新排除规则；来源切换、被排除、未知或敏感控件时终止。
4. 区分“直接从应用读取的选区”与“用户在输入框主动粘贴/输入的内容”。前者必须受来源策略限制，后者只能在明确提交后发送。

**验收标准：** 排除来源、未知来源、禁用状态和安全控件的选区正文读取及网络调用均为 0；鼠标在 A、焦点在 B 时按 B 执行策略；读取期间切换焦点或排除来源后，迟到结果不发送、不展示。

### R2 · P2 · 选区失败或打开菜单入口时自动读取剪贴板

**证据：源码与设计存在冲突。**

设计 §3.3 要求选区不可读时由用户自己粘贴，不自动读取系统剪贴板。实际 `handleSelection` 失败后传入 `revealManualWindow?(true)`，菜单入口也调用 `openManualWindow(prefillFromClipboard: true)`，最终通过 `NSPasteboard.general.string` 预填。

这不是后台持续监听，也没有证据表明预填内容会立即上传；当前实现仍要求用户点击 Translate。但“自动预填”不符合现有设计约定。

**解决方案：** 两类入口都打开空输入框并提示手动粘贴，移除失败路径上的自动剪贴板读取。保留正常系统粘贴操作；输入框内容仅在点击 Translate 后发送。无需修改既有规则来适配当前实现。

**验收标准：** 打开窗口及选区读取失败时，剪贴板读取、写入和网络调用均为 0；用户手动粘贴后仍不发送，点击 Translate 才发送可见内容。

### R3 · P2 · 阶段耗时日志输出固定字符串，零警告记录不准确

**证据：源码与历史日志确认。**

`Core/TranslationCoordinator.swift:560` 的 `logTiming` 虽然计算 `milliseconds`，日志字符串却缺少 Swift 插值所需的反斜线，输出的是字面量 `stage=(stage, privacy: .public)` 等内容。

`.build/v05-release.log` 对该变量报告未使用警告，与 `PROJECT_STATUS.md` 中 v0.5“本项目源码 0 warning”的记录不一致。

**影响：** 无法依照现有日志采集真实阶段、耗时和结果类别，也无法用 `stage=explanation` 等条件可靠验收。修复前不应给出延迟或性能结论。

**解决方案：** 恢复正确的 Logger 插值，只记录阶段、代次、耗时和有限结果类别。重新构建并用合成输入检查实际日志；同步更正旧的零警告声明，保留历史证据。

**验收标准：** 实际日志包含可读取的阶段和整数耗时，不含原文、译文、密钥、路径或窗口标题；相关未使用变量警告消失；性能结论仅基于实际采样。

### R4 · P2 · 选区快捷键无法检测注册冲突

**证据：源码确认，使用指南已披露限制。**

设计 §3.3 要求检查公开热键注册结果，并在冲突时提示。实际 `SelectionShortcutController` 使用 NSEvent 全局/本地事件监视，`isRegistered` 只反映监视器与辅助功能信任状态，不能证明快捷键未被其他应用占用。

**解决方案：** 在实施时核对 macOS 公开热键接口的能力并接入真正的注册/注销流程，明确处理冲突、设置切换和退出清理。若某些系统保留组合无法可靠检测，应准确说明限制，不能承诺全面冲突检测。若决定继续保留监视器方案，应将其作为明确的产品取舍同步修订设计，并把状态命名改为“监视可用”。

**验收标准：** 注册成功、可检测的冲突、切换快捷键和退出释放均有验证；同一次按键只触发一次翻译；无法检测的情况在界面与指南中如实说明。

### R5 · P2 · 手动窗口的 Copy result 接到了悬停卡片

**证据：源码确认，未实机复现。**

`App/AppDelegate.swift` 的 `manualModelActions()` 将 `manualActions.onCopy` 连接到 `coordinator.copyDisplayedText()`。该方法检查 `shownSnapshot` 并调用悬停 presenter。协调器已有专门的 `copyManualResult()`，但这个按钮没有调用它。

**影响：** 手动窗口有译文时，点击 Copy result 可能无动作；若仍有悬停快照，则可能复制悬停内容，而非当前手动译文。

**解决方案：** 将手动窗口 Copy 回调连接到 `copyManualResult()`，保持两个窗口的模型和复制目标分离。补充覆盖实际动作绑定的测试，而不仅测试复制方法本身。

**验收标准：** 无悬停卡片时可以复制手动结果；同时存在不同悬停与手动内容时，各自按钮复制各自内容；未点击时不写剪贴板。

### R6 · P1 · 锁屏清缓存和运行中策略变更缺少完整失效流程

**证据：源码确认相关方法仅执行了部分动作；实际竞态未复现。**

- 设计 §8 要求锁屏清缓存。`TriggerController` 将屏幕休眠、会话失活等事件交给 `externalChange()`，后者取消任务并重置悬停，没有清缓存。
- `translationPolicyChanged()` 只异步删除被排除来源的缓存；`translationCredentialsChanged()` 只异步清空缓存。两者没有主动使当前请求代次失效或取消请求。
- 请求捕获配置后，返回路径主要检查 generation。因此仅清缓存不足以保证删除密钥或排除来源后，正在返回的结果不再展示或重新写入缓存。

**解决方案：**

1. 为会话失活/休眠建立明确处理入口：先使旧请求失效并取消任务，再清理缓存。不要把普通切应用与需要清缓存的事件混成一种行为。
2. 排除来源、删除密钥或关闭云端翻译时，先更新策略代次、取消相关活动任务，再清缓存。
3. 在缓存命中、网络发送、结果展示及缓存写入边界检查代次与最新策略，避免异步清理与旧结果写回竞争。
4. 明确固定卡片在这些事件中的处理规则；至少不得因 Pin 保留活动请求或绕过新策略。

**验收标准：** 通过可控假服务挂起请求，删除密钥/排除来源/会话失活后再返回结果，确认旧结果不展示、不重新写缓存；下一次查询按最新策略处理。锁屏后缓存计数为 0。取消只保证本地失效，不能承诺撤销服务端已接收请求或计费。

1. **先收紧边界：R1、R6。** 修复选区来源验证与策略变更失效；使用假提取器、假服务和可控返回顺序建立回归。
